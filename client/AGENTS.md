# client

## Purpose

CLI + library crate. Owns directory scanning, format-v3 snapshot sync orchestration, local cache metadata, predictive hydration, summaries, and the watcher. Agent and history operations delegate to `feanorfs-agent-core`. It transports content without interpreting or merging it. Serializable result types are shared by library callers and `--json`.

## Ownership

- Crates: `feanorfs-client` produces binary `feanorfs` (sync + `serve` hub + agents) and library `feanorfs_client`. Agent workspace logic lives in `feanorfs-agent-core` — this crate re-exports `Runtime`, `Workspace`, and thin `agent.rs` / `conflicts.rs` wrappers.
- Modules under `client/src/`:
  - `lib.rs` — public API re-export surface. `open_api_client` performs mandatory metadata migration plus direct/mDNS/relay selection; `open_relay_api_client` is the diagnostic relay-only variant and still migrates first. Add new public functions here; downstream Rust consumers depend on this list.
  - `api.rs` — HTTPS/HTTP + in-process hub transport (`Backend::Http` | `Backend::Local`). `ApiClient::from_config` / `open_for_workspace`; private hubs add the invite-pinned public CA to normal reqwest/Rustls verification.
  - `hub.rs` — thin re-export (`pub use feanorfs_agent_core::hub::*`); `LocalHub` lives in `feanorfs-agent-core`. The `LocalHub` type is a JSON/state wrapper with durable `hub_state.json` + blob storage, not an Axum router. `feanorfs serve` uses the `LocalHub` from agent-core directly.
  - `migrate_sqlite/` — one-time SQLite → JSON/files migration coordinator (`migrate_workspace_stores`), journal (`metadata-migration.json`), cache state machine (`cache.rs`), hub state machine (`hub.rs`), WAL/fingerprint/archive helpers (`journal.rs`). Runs automatically on every `open_client_db` / `open_api_client` call before opening the store. Produces `.migrated-v1.db` archives next to each original SQLite file.
  - `cli/serve.rs` — `feanorfs serve`, `--gc-only`, and interactive `serve recovery export|import|rotate`; recovery passphrases are terminal-only and server-library code owns cryptography/persistence.
  - `recovery.rs` + `cli/recovery.rs` — versioned Argon2id + XChaCha20-Poly1305 offline workspace-capability kits and the interactive `recovery export|import` surface. Import decrypts/validates before local writes and passes `WorkspaceInvite` in-process to `run_start`; hidden tray input is a bounded stdin line, never argv/environment.
  - `cli/supervisor.rs` — the single supervised background job (`com.feanorfs.agent`; Task Scheduler `FeanorFS\Agent` on Windows). Owns the locked/atomic `supervisor.json` registry (workspace watchers, stopped workspaces, and canonical UTF-8 runner roots; lock `supervisor.lock`, lifetime single-instance flock `supervisor.instance.lock`), the secret-free `supervisor-status.json` snapshot with separate watcher/runner projections, legacy per-component job migration, one `supervisor-service-program` path-plus-Blake3 identity marker, and the 500 ms reconcile loop that spawns/terminates/restarts the hub worker, workspace watchers, configured runners, and tray with bounded backoff. Hub, workspace, and runner workers restart on any exit (clean or crash); only the tray respects a clean quit. Unix/macOS workers use fresh process groups with bounded TERM/KILL teardown; Windows workers start suspended, are adopted into verified private kill-on-close Job Objects, then resume. Newly spawned workers remain behind a parent-owned startup gate until their exact identity/status ledger is durable. Timeout, cancellation, and direct-child exit tear down descendants. Readers treat a status snapshot as live only while its recorded supervisor pid is alive, and stop/replacement paths use exact native process-start identity plus exact executable/argv checks where supported; stale or unverifiable identities remain fail-closed instead of being guessed. Runner stop/recovery also requires a durable workspace-specific registry reconciliation acknowledgement bound to the supervisor identity; fresh disabled/unregistered setup/stop skips an impossible ACK, while stale authority still fails closed. macOS/Linux run the tray inside the supervisor; Windows keeps the interactive tray task separate.
  - `cli/hub_service.rs` — first-machine automatic private-hub lifecycle. Owns `~/.feanorfs/hub-data`, the hub worker (`service hub-run <data-dir>` runs as a supervisor child), atomic `listen-port`, readiness/manual-hub detection, HTTP→TLS local migration, CA-bound portable invite export, and optional outbound opaque-tunnel workers loaded from private atomic `hub-data/relay.json`. It composes server-library TLS/auth/runtime primitives and never owns blob logic.
  - `cli/service.rs` — workspace service surface (`service install|status|start|stop|uninstall`), consumer `start`/`stop` lifecycle hooks, hidden `service run <folder>` watcher worker, hidden `service supervise`, `refresh-installation`, and tray discovery. All background state lives in `supervisor.rs`; this module owns the CLI contract and messages.
  - `cli/agent_runner.rs` — shared foreground/supervised execution loop for an already-configured format-v3 runner. Owns cursor catch-up/admission, guarded refresh, one-at-a-time child launch, a fail-closed startup gate that prevents configured code from executing before `mark_spawned`, bounded stdin invocation, native process-tree teardown after cancellation, timeout, or direct-child exit, and interruption-aware fail-closed terminal observation/publication with one shared bounded pre-cancel completion window. A local refresh/preparation failure before launch records `preparation_failed`; durable lifecycle authority remains in agent-core.
  - `cli/runner.rs` — visible `agent runner setup|start|stop|status|reset|remove` controller. Resolves and canonicalizes trusted argv before mutation, projects only redacted local state, registers the hidden `service runner-run <canonical-workspace>` child under the existing supervisor, and shares the exact `agent_runner::run_worker` loop for explicit foreground execution.
  - `cli/pair.rs` — client-to-client pairing. `fnp1` uses secret-free ephemeral mDNS on LAN; `fnp2` embeds a public relay URL/128-bit session plus an 80-bit client-only secret for outbound WSS rendezvous. Both run the same SPAKE2 + AEAD invite delivery/key confirmation and attempt/expiry limits. Hidden `pair --tray` emits only the ephemeral capability and TTL to the bundled tray's captured pipe.
  - `cli/tray.rs` — hidden tray adapters. `tray overview` additively wraps routine worker-snapshot status and the recent registry in one JSON response for the desktop's recurring refresh. Receiver-side `tray join <folder>` reads one bounded stdin pairing capability, validates it into a zeroizing `PairCode`, and delegates in-process to `run_start`; no capability enters argv/environment/logs.
  - `endpoint.rs` — pre-operation private-hub endpoint selection. Derives the managed `.local` hostname from the pinned public CA, tries exact-CA-and-port same-machine loopback before any potentially blocking system `.local` lookup, then authenticated direct and CA-correlated mDNS paths, and finally the configured inner-TLS relay without changing trust or TLS hostname verification.
  - `join_preflight.rs` — mutation-free non-empty join classification. Scans through scratch state under the encrypted mirror policy, reaches the authenticated remote snapshot through the same direct/loopback/mDNS/relay endpoint selector as normal sync, bounds path examples, and blocks legacy-transport oversized files before configuration or upload.
  - `cli/history.rs` — human and JSON `log` / `undo` output.
  - `cli/update.rs` — workspace-independent official stable-release lookup. Owns the HTTPS-only timeout/size bound, `semver` comparison, draft/prerelease rejection, exact GitHub tag-URL validation, typed human/JSON result, and the no-download/no-execute boundary used by the tray.
  - `commands.rs` — sync/push/pull/hydrate/cat/status via unified `run_sync_pass`. Hydration uses agent-core's locked transactional materializer; `cat` accepts only safe relative paths and reads through the descriptor-anchored workspace root. Owns `MirrorState` with `human_label()`. Returns `Serialize`-derived structs. No `println!` — UI in `main.rs` / `cli/`.
  - `conflicts.rs` — workspace conflict detection, registry, `resolve_conflict`, join/attach divergent-path guards, placeholder corruption, post-upload create/create, case conflicts. `seed_last_synced_from_server` skips same-path hash mismatches. `conflicts history` reads `conflict_resolutions`.
  - `conflict_artifacts.rs` — shared `.original`/`.local`/`.cloud` writer for agent and workspace conflicts.
  - `cli/integrator.rs` — `agent integrator assign|status|revoke|resume` and `conflicts materialize` thin adapters over `feanorfs_agent_core::integrator`; human output shows only selected agent/state/next action, `--json` emits canonical types.
  - `cli/mcp.rs` — MCP request adapter. Every tool input is parsed through a `deny_unknown_fields` typed contract; unknown fields or wrong optional-field types return JSON-RPC `-32602` before any tool mutation. Tool schemas declare `additionalProperties: false` and documented optional defaults remain stable.
  - `cli/events.rs` — long-lived metadata-only NDJSON stream. Private typed variants preserve the shipped wire shapes; transient status/head/signal failures retain cursors and retry instead of ending the stream, and `agent_message_cursor_reset` is emitted before wakeups returned by that reset poll.
  - `cli/` — CLI helpers (`util`, `agent`, `conflicts`, `integrator`, `serve`, `start`, `mcp`, `events`, `workspace`, …). Keeps `main.rs` under 1k lines.
  - `fs_util.rs` — `atomic_write` (temp + rename), `file_mtime_ms`.
  - `local.rs` — `Config` (`hub_local`, `format_version`), `ClientDb`, `scan_local_directory`.
  - `agent.rs` — re-exports `feanorfs_agent_core` agent ops; CLI `--json` uses the same shapes as [docs/agent-api.md](../docs/agent-api.md).
  - `predictive.rs` — `record_access_with_recent`, `prefetch_related` (top-5 siblings, 0.95 decay). Local-only.
  - `recent.rs` — locked, atomic `~/.feanorfs/recent.json` registry shared by `start`, `stop`, and the tray. List reads use a shared lock; mutations use the existing exclusive lock plus atomic replacement. An absent global state root returns an empty projection without creating directories, a lock, or a store. Removing an active workspace deterministically selects the next entry.
  - `summary.rs` — `diff_since_last_session`, `commit_session_marker`, `render_via_summary_tool`. Zero-knowledge — never ships file contents to a remote LLM.
  - `watch.rs` — debounced (500 ms) filesystem watcher that drives `do_sync` on mutating events and ignores non-mutating access/open events emitted by its own scan. Watcher path MUST be the workspace `current_dir`, never `"."`.
  - `tray.rs` — tray dashboard aggregation (`do_tray_status`, `do_tray_status_with`, `build_conflict_show`). Agent summary cached in the private global workspace state as a size/entry-bounded `tray-agent-cache.json` (30 s TTL); `invalidate_agent_cache` after land/keep. The managed worker publishes a size/entry-bounded secret-free `worker-status.json` snapshot after every successful or failed sync attempt (`publish_worker_status`); routine tray refreshes resolve the private workspace state once and read the bounded worker snapshot, bounded agent cache, public workspace ID, pause/watch markers, and sync-lock metadata. They do not resolve protected credentials, open `local_state`/workspace cache, scan the project, contact the hub, or acquire the sync lock. `invalidate_worker_status` yields a constant-cost transitional result until the worker republishes; `tray status --fresh` is the only fresh scan path.
- Local runtime data lives under opaque `~/.feanorfs/workspaces/<id>/` directories, never in the project. Live state includes `local_state.json`, config, refs, objects, conflicts, and embedded hub data under that private global workspace directory.

## Local Contracts

- Unit and integration test crate roots link `feanorfs-test-support` once. The pre-main temporary profile is inherited by real-CLI subprocesses; tests set alternate homes only on `Command` and never mutate HOME/FEANORFS_HOME after startup.
- All paths stored in `local_state.json` use forward slashes via `feanorfs_common::normalize_path`. Always normalize before cache lookup or mutation.
- CLI and managed-worker file logging defaults to `info`, waits up to two seconds for the cross-process rotation/write lock, reopens the active path per record, uses private creation permissions, and hard-caps both `feanorfs.log` and its single rotated `.old` generation at 10 MiB each. Tray-facing commands are latency-sensitive: global tray commands select the global log without resolving `$HOME` as a workspace, and every tray command tries the log lock once before degrading to a sink. Other still-contended writers degrade after the bounded wait rather than blocking the product indefinitely. An existing retired global-root log is repaired under the same cap/private mode; fresh installs never recreate it. Never restore an unbounded persistent debug writer.
- Legacy SQLite stores (`local_cache.db`, `agents/<name>/.feanorfs/local_cache.db`, `hub-data/db.sqlite`) are migrated one time to JSON/state files on first open. Migration is idempotent: re-running is a no-op once the journal shows `Archived` for all stores.
- Avoid redundant hashing: check `local_state.json` first and re-hash only if `mtime`/`size` differs from the cached entry. For unchanged placeholders (`hydrated=false`, `size==0`), reuse the cached hashes so the sync diff remains correct without downloading bytes.
- **Migration contracts:** the private global workspace `metadata-migration.lock` (`fs2` exclusive) gates `metadata-migration.json`, which records store key, legacy source paths, fingerprints, phase (`Discovered → Imported → Verified → Archived`), and archive paths; archives land next to each original SQLite as `.migrated-v1.db` (+ `-wal` + `-shm`) with hash-collision guard. Resuming after interruption reads the journal and skips completed phases.
- **Sync scope:** mirror the working directory (including gitignored/untracked paths). Hard skip legacy `.feanorfs/`, `.feanorfsignore`, `.git/`, `.jj/`, symlinks, and nested directories declaring a valid `CACHEDIR.TAG` (workspace-root tags are exempt). Small frozen `DEFAULT_IGNORES` plus optional rules stored only in private global workspace state — do NOT create an ignore file or honor `.gitignore`. Rationale and admission criteria: [docs/sync-scope.md](../docs/sync-scope.md). Do not grow `DEFAULT_IGNORES` without meeting all three criteria there.
- Zero-knowledge: seal file bytes before transport and verify ciphertext hashes before decrypting. Format-v3 uploads file blobs through opaque object storage and commits encrypted trees through head compare-and-swap.
- Large format-v3 files are represented by an authenticated encrypted manifest and fixed 8 MiB AEAD chunks through the same opaque object API. Human and JSON sync results report a bounded count/examples notice for files above the former 100 MiB limit; legitimate files proceed, while copy/build artifacts can be excluded with `feanorfs ignore`. Hashing and upload stream one descriptor-anchored file, authenticate registry-known chunks, and retain at most four pending encrypted chunks. Hydration, predictive fetch, conflicts, agent refresh/land, migration, hub transfer, and retained manifests must preserve the same containment, chunk-integrity, and reachability rules.
- Sync, lazy pull, explicit hydration, predictive hydration, agent land/refresh, and undo support file↔directory transitions through agent-core's one-plan staged materializer under the sync lock. Concurrent ancestor/descendant shapes and filtered-conflict prefix collisions fail before head/worktree mutation; untracked or symlink children are preserved. Tests cover both transition directions, rollback injection, crash-journal recovery, executable conflict legs, symlink substitution, and missing undo blobs.
- Result types are `Serialize`-derived. The `--json` CLI flag and `feanorfs_client::` library callers MUST see the same shape; do not add `println!` in `commands.rs` or `agent.rs` — keep UI in `main.rs` only.
- MCP `sync_status` is intentionally a compact projection of `StatusResult`: preserve mirror state, local-file count, actionable pending paths, conflict/offline state, rollback warning, and skipped-symlink count, but never serialize the complete `local_files` map into routine MCP responses. CLI `--json status` and library callers retain the full result.
- Human `status` output shows at most five deterministic symlink examples plus the total; `StatusResult.skipped_symlinks` and `--json` retain the complete sorted list for automation.
- Workspace conflicts: bare `feanorfs conflicts` or `conflicts list`; `keep`; `show [--open]`. Registry and artifacts live only in the private global workspace state. `ResolveKeep::Cloud` on `edit_delete` conflicts removes the local file and uploads a tombstone when the cloud artifact is a deletion sentinel.
- `agent status` (or bare `agent`) lists agents with one-line state when online; hidden `agent list` keeps legacy JSON shape. `agent status <name>` / hidden `agent check` peek via `/api/sync/peek`.
- Agent signals: `agent send <to> --kind <request|status|result|blocked> [--about <id>] [--reply-to <id>] [--from <name>] <body>` publishes one encrypted no-file-change snapshot; `agent inbox [--for <name>] [--after <head>] [--limit <n>]` reads reachability-delta signals with `cursor`/`cursor_reset` semantics. Sender defaults to `FEANORFS_AGENT`, then `human`. Human `log` renders recognized signals concisely; `--json` history is unchanged. Protocol: [docs/agent-communication.md](../docs/agent-communication.md).
- Agent workspaces isolate DATA, not processes — `agent run` is cwd-scoping only. Never claim sandboxing; link [docs/threat-model.md](../docs/threat-model.md) § Process isolation. `agent run` also exports the validated absolute shared control root as `FEANORFS_WORKSPACE_ROOT` so nested FeanorFS signal/MCP commands use shared refs while the child process remains cwd-scoped to the agent worktree. Nested MCP `conflicts_keep` resolves a relative `file` source against that shared control root; absolute sources remain unchanged.
- Visible agent-runner control is local-first: `setup` requires an existing format-v3 workspace and spawned agent, stores only canonical program/fixed argv plus body-free runtime state, and leaves execution disabled; `status` never contacts the hub or exposes argv, message bodies, process output, or credentials. Supervised `start` uses only the existing single supervisor and hidden canonical-workspace worker argv. `start --foreground` hands ownership to the invoking terminal: Unix Ctrl-C/SIGTERM and Windows Ctrl-C/Ctrl-Break cancel that loop, while supervised `stop` does not control it. `stop` disables admission before unregistering and preserves runner/agent state, waiting for a durable workspace-specific reconciliation acknowledgement whenever supervisor authority exists. Fresh/idempotently disabled and unregistered setup/stop with no supervisor authority skips an impossible ACK; stale authority remains fail-closed. The five attention reasons are `cursor_reset`, `pending_overflow`, `ambiguous_execution`, `delivery_unknown`, and `preparation_failed` (local refresh/preparation failed before launch). `reset` and `remove` require explicit `--discard-pending`; no attention state is automatically replayed.
- Predictive hydration is local-only: `file_access_log` never leaves the client.
- Local-hub workspaces (`hub_local` / `start --local`): in-process transport via `LocalHub` (agent-core JSON/state at the private global workspace `hub_data_dir/hub_state.json` + `blobs/`). `hub.rs` is a re-export shim; the Axum router for `feanorfs serve` is in `cli/serve.rs`. Embedded hubs are not portable; use the managed private hub for sharing.
- Sync reconciliation compares local and head trees with the private global workspace `refs/last-synced`. The `last_synced_files` and `agent_snapshots` tables are removed in format v3. `mtime` remains cache and rollback evidence, never content identity.
- Format-v3 migration journals old key, target key, fence token, and phase in private global workspace `migration-v3.json`; this is distinct from the SQLite import journal `metadata-migration.json`. Rekey never persists the target key before reseal, parentless head CAS, server stamp, and local finalization complete. Resume the command after interruption.
- Rekey requires clean or landed agent workspaces because old-key agent base refs cannot cross the key boundary.
- Onboarding: `start [target] [folder]` accepts an `fnh1-…` secure hub invite, full `fnr1-…` workspace invite, single-use LAN `fnp1-…` or off-LAN `fnp2-…` pairing capability, or folder. With no workspace or cached connection, a folder target creates the automatic secure private hub; `--host` explicitly selects that path and `--relay <URL>` adds outbound-only off-LAN reachability without a new command. Every branch converges on link/create → initial sync → workspace service + tray. Hidden `tray join <folder>` is the bundled receiver UI adapter: it accepts only bounded stdin `fnp1`/`fnp2`, constructs the existing zeroizing pairing type, and enters `run_start`. Hidden `attach`/`init`/`setup` configure only.
- Joining a non-empty folder first produces bounded local-only, mirror-only, identical, and same-path-different counts without touching destination setup or files. The sender's normalized, bounded global ignore policy travels inside the encrypted invite; a differing known policy requires confirmation and is applied atomically to private global state before the first real scan. Terminal automation may use public `--accept-join` only after reviewing the preview. Hidden tray join keeps the full invite inside the CLI child and exposes only the typed preview over bounded stdout before accepting a bounded public decision on the same stdin pipe.
- Positional target detection must preserve Windows drive paths and ordinary colon-bearing folder names. Scheme-free server targets are accepted only when they are unambiguous `localhost`, IP, or dotted-host values with an explicit port; custom single-label hosts require `https://`.
- On an already configured folder, `start fnh1-…` is a hub-trust refresh: require HTTPS plus a bearer token, authenticate the candidate CA/token and existing opaque head before writing config, and preserve workspace ID, E2EE key, format, refs, files, and history. A failed probe must leave old connection settings untouched.
- New mirrors without an explicit `--workspace` receive independent opaque random `fsw1-…` IDs. Never restore a shared `default` consumer ID: adding a second folder must not attach it to another mirror. Invites and pair codes preserve their existing workspace ID.
- New/link format-v2/v3 paths validate a manual E2EE key before writing workspace or global configuration. Accept only the canonical 64-character lowercase-hex recovery-key shape; automatic setup generates it. Legacy format-v1 keys remain loadable for migration, and `migrate --rekey` is the path for historical human-chosen keys.
- Workspace recovery kits contain the complete portable capability only as authenticated ciphertext. Use Argon2id v19 (64 MiB, three iterations, one lane), XChaCha20-Poly1305, a distinct authenticated domain, metadata-plus-stream bounded reads before parsing, atomic `0600` Unix writes, atomic no-clobber publication unless overwrite is explicit, and fail-before-write import. The kit is not a blob backup. Decrypted invites remain in-process and converge on `run_start`; passphrases use terminal input or the bundled tray's bounded stdin pipe and never argv/environment/logs.
- Never use an accept-invalid-certificate client. Private hub CAs come from `fnh1`/`fnr1` capabilities; unauthenticated mDNS fingerprints are informational and must not create trust-on-first-use.
- CLI surface: visible verbs include `folders`, `log`, and `undo` alongside sync, workspace, agent, and conflict commands. `folders` projects the same locked recent-workspace registry as the tray, with human or global `--json` output. Hidden tray commands continue to feed `feanorfs-tray`.
- `conflicts keep --all --local|--cloud` validates every selected version before mutation, then resolves every pending conflict with one scan, snapshot publication, and durable history update. Cloud deletion sentinels remove their local paths. The tray requires strong count-and-consequence confirmation; neither path merges file content. Human conflict list/history output is capped at 20 entries and human diffs at 64 KiB, while JSON remains complete and treats a closed stdout reader as a clean exit.
- `update` is advisory release awareness, never an installer: make one manual bounded HTTPS-only, no-redirect lookup of the versioned official stable GitHub release API, parse with the direct maintained `semver` dependency, and return one typed status (`up_to_date`, `update_available`, `development_build`). Reject draft/prerelease/malformed metadata and any URL other than the exact matching official tag page. `update --periodic` reuses the per-machine secret-free `~/.feanorfs/update-state.json` throttle result (24 h window) so the CLI and tray report the same answer without repeated network checks; `doctor` exposes `update_available` from that cached state. Never download, stage, install, execute, or silently open an artifact; signed/checksummed platform installers remain authoritative.
- `start` reports pairing, initial sync, workspace-service installation, and tray registration as separate stages. A failure after configuration preserves the encrypted workspace identity and names the exact resumable stage; rerunning `start -- <folder>` rechecks completed idempotent stages and repairs what remains without pairing again. First-machine hosting installs the global hub service before creating the workspace. `--foreground` retains the terminal watcher and `--no-watch` remains one-shot for the workspace (the hosted hub still persists). Service metadata contains only canonical workspace/hub-data paths; keys/tokens stay in protected files or the OS store.
- `start` protects new and legacy local credentials through agent-core's OS-store facade before background execution. Embedded hubs never inherit a cached token from an unrelated remote hub.
- `service install|status|start|stop|uninstall [folder]` is the recovery surface over the single supervisor job. Install/start add the folder to `supervisor.json`; stop moves it to the stopped set; uninstall removes it. The tray is resolved from an explicit override, a colocated desktop product, `/Applications/FeanorFS.app` on macOS, or `PATH`; on macOS/Linux the supervisor spawns it, on Windows it is registered as the only interactive Task Scheduler task. Windows hub/workspace/tray status uses the stable Task Scheduler state enum, not localized text or task existence alone; only the tray task uses `InteractiveToken`.
- Hidden `service refresh-installation` is the native-installer handoff after replacing executables. It migrates legacy per-component jobs into the registry, re-adds available configured recent workspaces, restarts the single supervisor job when its path-plus-hash identity changed, refreshes an owned TLS private hub in-process, and lets the supervisor re-register the tray against the selected CLI. It receives no folder, key, token, invite, or route through argv/environment and does not perform sync or change workspace identity.
- Windows task registration must store the executable and arguments as separate Task Scheduler fields; never flatten them through `schtasks /TR`, whose 261-character limit rejects ordinary long install/workspace paths. Task actions contain only the supervisor subcommand or the canonical tray program and no credentials or capabilities.
- Tray `watching` state and sync-lock checks must reuse agent-core's native cross-platform process-liveness probe; a live Windows watcher cannot be reported dead or have its lock treated as stale.
- Consumer `stop [folder]` composes service uninstall with locked/atomic recent-workspace removal. It refuses unmanaged active watchers and preserves private global workspace state, working files, credentials, remote snapshots, and any private or embedded hub; rerunning `start` resumes the same workspace.
- Hidden `tray forget-unavailable` is the tray's explicit stale-list repair. Under the existing recent-store lock, remove only entries whose folder is missing or whose private global workspace config is unavailable (a deleted folder is always unavailable even when its state survives), select the next available active entry, and atomically replace `recent.json`. Never touch workspace files, credentials, services, hubs, or remote snapshots; the tray must confirm first because an external drive may only be disconnected.
- Hidden `service hub-run <data-dir>` is only the OS-supervised worker. Do not expose hub lifecycle vocabulary in normal onboarding. `start --host` safely converts a matching local legacy HTTP hub to native TLS while preserving its token; it refuses an active manual process and unrelated workspace identities.
- `doctor` accumulates secret-free named checks for global/workspace config, E2EE, format-v3 trees, automatic workspace sync, tray registration, private-hub persistence, authenticated endpoint reachability, remote workspace evidence, and local state. Human and `--json` output share the same result; one failing check must not prevent later checks from running. A manually reachable but non-persistent workspace or hub never passes.
- `doctor --migration-report` is a separate local evidence mode: read only the minimal `format_version` field from current/recent workspace config files, never resolve credentials or contact a hub, deduplicate folders, and emit a versioned aggregate schema only. Do not include paths, workspace IDs, labels, endpoints, credential references, routes, keys, tokens, or capabilities. Lock the exact JSON key set in tests. An unreadable recent registry, missing/malformed config, unsupported format, empty profile, or any format-v1 workspace must prevent a retirement-ready result; this local signal never authorizes removing legacy decryption without broader field evidence.
- A fresh automatic host prefers `https://127.0.0.1:3030`; if the port is occupied, it scans the bounded stable range 3030–3130 before requesting an OS-assigned last resort, then atomically persists the nonzero result as `0600` `hub-data/listen-port`. Existing hubs without that record retain 3030. The worker reads the validated port from the protected data directory, while service argv remains only `service hub-run <data-dir>`. TLS readiness, the relay tunnel, mDNS, diagnostics, and portable invites must use the persisted port. Exported full invites rewrite only loopback to the stable CA-derived `.local` hostname after the invite public CA matches `hub-data/tls/ca-cert.pem`; the port is preserved. The hub auto-tracks interface addresses. Receiving clients retain normal TLS verification, and legacy numeric URLs migrate only after a bearer-authenticated CA-verified probe.
- Private-hub disaster recovery is an advanced `serve recovery export|import|rotate` surface, not part of onboarding. It prompts for the bundle passphrase, passes no secret through argv/env, and delegates identity validation, encryption, locking, fencing, persistence, and fresh CA/token generation to `feanorfs-server`. Rotation preserves opaque storage but requires every existing client to authenticate the replacement `fnh1` capability.
- On macOS/Linux, `service stop` moves the workspace into the registry's stopped set and waits for the supervisor to terminate its watcher and for the private global workspace sync lock to clear; `service start` moves it back. The supervisor job itself is never uninstalled by per-workspace operations, so the Settings background-item entry stays stable.
- On every Unix desktop, stopping a managed workspace waits up to five seconds for both the service process and its sync lock to clear before `start` performs the foreground upgrade sync.
- The single supervisor job persists a path-plus-Blake3 executable identity (`supervisor-service-program` under the global state root) and reinstalls when bytes change even at the same package path; legacy per-component `service-program` markers are removed by migration. Resuming any locally owned workspace also checks/restarts the private hub through the supervisor; `--host` is not required for package upgrades. Background `start` temporarily moves an existing managed watcher to the stopped set before its initial sync, restores it on failure, and drops foreground workspace handles before the supervisor launches the replacement worker, so upgrades neither race the sync lock nor leave old mapped binaries running.
- `pair` is client-layer introduction, not a hub endpoint. Managed hubs deliver their CA-bound stable hostname; custom loopback hubs retain the accepted-interface IP fallback. The `fnp1` secret never appears in mDNS, tray receiver argv/environment/logs, or hub storage; the full invite is SPAKE2-authenticated, AEAD-encrypted, key-confirmed, and zeroized where owned. Hidden tray presentation may emit only the ephemeral code and TTL through captured stdout and must stop the child when its native dialog closes. Receiver-side tray input is masked and bounded, uses the same `PairCode` and `run_start`, and never duplicates validation or exchange logic. Preserve full `fnr1` as the non-LAN fallback.
- `fnp2` off-LAN pairing requires WSS except loopback tests, embeds the relay URL and 128-bit public session in the zeroized capability, keeps the 80-bit secret out of relay URLs/state/logs, and reuses SPAKE2/AEAD/key confirmation unchanged. Public HTTPS hubs need only rendezvous; owned private `.local` hubs first persist a validated 256-bit tunnel route through `start/pair --relay`, restart the hub service transactionally, and include that route in the encrypted invite. The tray reuses stored relay settings automatically.
- Relay-backed sync must preserve the original HTTPS hostname as SNI, pinned/system CA verification, and bearer auth. Direct/mDNS paths are attempted first by the CLI; relay fallback is bounded and never places the route, token, or invite in service argv/environment/logs. The hub worker reads the route only from atomic `0600` `hub-data/relay.json`, so it does not depend on ambient `HOME`. `doctor` performs a real relay-only authenticated probe when configured.
