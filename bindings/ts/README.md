# @feanorfs/agent

Native Node.js bindings for the FeanorFS agent SDK (`spawn` / `status` / `refresh` / `land` / `clean` / `conflicts keep`).

**Status:** release-ready, not published. CI can manually build and verify five
native packages as a dry run, but application release tags do not publish npm
packages. Build from source or install local tarballs.

Supported packages:

- `@feanorfs/agent-darwin-x64`
- `@feanorfs/agent-darwin-arm64`
- `@feanorfs/agent-linux-x64-gnu`
- `@feanorfs/agent-linux-arm64-gnu`
- `@feanorfs/agent-win32-x64-msvc`

## Local host build

Requires Rust (the repository toolchain) and Node 18+:

```bash
# from the repository root
cargo build -p feanorfs-client   # optional: used by the integration test setup

cd bindings/ts
npm ci --ignore-scripts
npm run build                    # builds only this machine's native addon
npm run create-npm-dir           # refreshes the five platform manifests
npm run assemble-metadata
npm run verify-metadata
FEANORFS_BIN=/exact/path/to/feanorfs npm test
```

The host addon is written to `feanorfs-agent-node.<platform>.node` in this
directory. `index.js` (generated by napi-rs) loads it. A local host build is not
five-target release evidence.

## Five-target package assembly

Full assembly requires exactly five genuine native artifacts built from one
source SHA in `bindings/ts/artifacts/`: macOS x64 and arm64, Linux GNU x64 and
arm64, and Windows x64. The manual `npm-release.yml` workflow builds that matrix
on the corresponding runners, merges the raw artifacts in a clean packaging
job, and then runs:

```bash
npm run create-npm-dir
npm run assemble-packages
npm run verify-packages
```

Never copy or rename a host addon to stand in for another target. Full
verification parses each Mach-O, ELF, or PE header and rejects a filename whose
CPU or object format does not match its configured target. If all five
same-SHA artifacts are unavailable, run the local metadata/test path above
rather than weakening or partially skipping `verify-packages`.

## Usage

Typed async API (recommended):

```javascript
import { spawn, land, clean } from '@feanorfs/agent'

const result = await spawn('/path/to/workspace', 'worker', { noSync: false })
await land('/path/to/workspace', 'worker')
await clean('/path/to/workspace', 'worker')
```

Low-level JSON strings:

```javascript
import { native } from '@feanorfs/agent'
const json = await native.agentSpawn(root, name, {})
```

Each call opens the workspace fresh (`local_state.json` + transport). Pass the workspace root path every time.

## Contract

JSON shapes match [docs/agent-api.md](../docs/agent-api.md). TypeScript interfaces are in `contract.d.ts`.

## Test

```bash
FEANORFS_BIN=/path/to/feanorfs npm test
```

Uses the CLI only to create a local-hub workspace; the loop itself runs through the native module.

Release assembly also runs `npm pack --dry-run --json` for all six packages,
installs the facade plus host tarball with the registry disabled, and executes
the same loop. `scripts/publish-packages.mjs` makes retries idempotent by
matching registry tarball integrity and metadata before any publish.
